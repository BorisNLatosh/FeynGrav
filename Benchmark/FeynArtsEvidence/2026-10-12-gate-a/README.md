## Observations (not a completed acceptance gate)

- The first `probe` fresh kernel initialised a custom generic/classes model with `KinematicIndices[T]={Lorentz,Lorentz}`, `KinematicIndices[U]={Lorentz}`, and oriented non-self-conjugate `U[1]`. An internal `T` line returned four transported index slots and an internal `U` line two. `FCPrepareFAAmp` converted their metric and propagator-denominator heads; it left the deliberately custom external `FAPolarizationTensor` marker unchanged.
- The second `amp` fresh kernel built one toy external-tensor tree and a diagnostic ghost-loop insertion. `FCFAConvert` retained the custom tensor marker; `Truncated -> True` did not amputate it because this disposable generic model did not define an `M$TruncationRules` entry. The ghost bubble produced `CreateFeynAmp::nocoupl` for the reversed ghost ordering, leaving a `C[0][...]` unresolved. Neither the ghost loop nor the tensor external state is verified by this first model.
- The corrected `ordered` model defines `M$TruncationRules`, metric orderlessness, a noncommuting vector `U` and normal FeynArts ghost-chain handling. Its toy external `T` tree converts with **two open Lorentz indices** and no custom marker; the tiny ghost bubble converts with no unresolved `C[0]`. The separate `check-ghost-sign.wls` compares FeynArts' ghost and commuting-control loops after contraction: the exact contracted sum is zero. This is an **internal statistics sign control**, not independent FP action or full one-loop validation. Its initial run failed due to an overstrict test of the insertion expression's shape; `check-ghost-sign-initial.log` retains that failed input outcome, and the corrected script and successful log are preserved.
- `check-dimension-reload.wls` tested two **distinct toy model identities** in one fresh kernel: the second's doubled coupling produced an exactly doubled `D`-dimensional open-index amplitude, and a composite `p-r` momentum converted to dimension-`D` FeynCalc pairs/propagators. The second initialisation emitted `RuleDelayed::rhs` warnings from the installed FeynArts model loader; actual expected coefficients matched, but warning-free model reload is not established.
- No source rule, independent symmetry factor, complete gauge-fixing functional, four-graviton tree or one-loop graviton integrand has been validated by these probes. `ExcludeTopologies -> {Tadpoles}` in the diagnostic ghost-only scripts is **not** acceptable for the eventual complete one-loop construction.
