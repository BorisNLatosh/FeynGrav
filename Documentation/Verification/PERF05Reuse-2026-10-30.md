## Implementation and identity

The actual algebra in `cfcCollectScalarOnce` retains increment 3's domain and
replacement rules. `cfcCollectScalar` now reuses exact sorted inputs under one
immutable generated mapping/rules context. It remembers successful results,
settled-output aliases and conservative rejections; changed coefficients receive
new keys and new FORM jobs start empty. Native argument interning supplies keys,
with complete-argument validation; there is no approximate hash comparison.

The private collection profile initially retains at most 64 ready entries;
1,024 eligible visits bound lookup work separately from the unchanged arithmetic
allowance. Capacity exhaustion or an unkeyable argument leaves the full current
coefficient untouched. Existing hits remain usable at capacity until visits are
spent. This is a conservative storage choice, not a measured performance optimum.
No new public option, mapping grammar, mathematical identity or fixed-point loop
is introduced. Existing polarisation caches and counters remain separate.
