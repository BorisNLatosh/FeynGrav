# Library refresh verification — 8 October 2026

## Scope and outcome

Regenerated all 90 inventoried extensionless libraries into a separate directory with the current generator and TFORM 5.0.2 (eight workers). Each specific generation command was run twice; all 90 results were byte-identical between passes. No stored libraries were used as input to generation.

84 libraries passed equivalence checks and were published. Six libraries retain their pre-refresh contents because equivalence was not established. This is therefore a partial verified refresh, not a claim that every stored library matches the current generator.

Existing generator and rule edits were preserved. No interaction formula was changed in this refresh. No commit was made.

## Verification

- Both generations completed for every inventoried case, using fresh kernels for each specific generation request.
- Libraries were read under the same symbol contexts as FeynGrav's importer.
- Comparisons used exact expression identity, expanded exact residuals, or bounded FeynCalc Dirac/Lorentz simplification.
- For the two four-gluon libraries, FeynCalc comparisons remained inconclusive. The exact new-minus-old expressions reduced to zero through CalcFormCalculate colour reduction. These checks use the converter and are not independent validation of its colour implementation.
- All 12 library importers passed against an isolated candidate set containing the 84 replacements and six preserved libraries. Scalar composite-momentum and quark–gluon argument-binding checks also passed (14 checks total).
- Every repository destination was checked against its pre-run checksum before publication, protecting concurrent edits. Publication used a staged file and atomic replacement for each changed library.
- This did not rerun the full converter regression or benchmark suites, and did not independently rederive interaction formulas.

## Libraries deliberately retained

- `GravitonAxionVectorVertex_1` and `GravitonAxionVectorVertex_2`: the legacy epsilon expressions contain momentum names in Lorentz-index slots and four-dimensional notation, unlike the corrected generator's D-dimensional momentum slots. This is not established as a representation-only change.
- `HorndeskiG5_0_1_1`, `HorndeskiG5_0_1_2`, `HorndeskiG5_1_1_1`, and `HorndeskiG5_1_1_2`: nonzero comparison residuals remain. Their cause requires a separate rule/library audit; neither version is declared correct here.

The staged new versions of these six files are retained for investigation. They have not replaced the repository copies.

## Reproducibility and evidence

[Machine-readable per-file results](LibraryRefresh-2026-10-08.json) record comparison methods, sizes, checksums and publication decisions. Byte stability was checked within the same kernel for each pair of repeated generation calls; calls for different parameter sets used fresh kernels. This does not establish cross-version or arbitrary cross-session byte stability.
