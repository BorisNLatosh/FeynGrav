## Scope and result

The self-contained `GR-SU-N-Yang-Mills` bundle contains all 16 families through
κ² per vertex for pure SU(N) Yang–Mills coupled to GR. D, N and the gauge coupling
remain symbolic. The fixed gauges are GR epsilon 2 and YM epsilon −1. Quarks,
loop validation, other gauges and higher orders are excluded. The existing four
native model bundles and user notebooks are unchanged.

See the [model guide](../../FeynArts/Models/GR-SU-N-Yang-Mills/ModelGuide.md)
for the action, fields, propagators, determinant representation and native recipe.
The manifest records input hashes, all family/basis sizes, coupling hashes and
model-file hashes. Construction uses matching generic/classes closure, through
the existing `Basis.wl` and `ModelBuilder.wl` machinery, with narrow typed colour
translation in `YangMillsModelBuilder.wl`.

## Source defect and correction

The contracted and uncontracted `GravitonThreeGluonVertex` and
`GravitonFourGluonVertex` routines multiplied their geometric tensors by n!, but
omitted κ^n. The tensors themselves contain no gravitational coupling. Adding
κ^n in all four routines restores the required perturbative order; no compensating
factor is inserted into the native model builder.

Only these four stored files were regenerated and replaced locally:
`GravitonThreeGluonVertex_1`, `_2`, `GravitonFourGluonVertex_1`, `_2`.
Each regenerated file equals the preceding tensor times its missing κ^n exactly,
after consistent colour normalisation. The next section independently verifies
that the corrected result agrees with the action, rather than relying on that
relative comparison alone. These four stored libraries are tracked repository
files. The native bundle loads without them.
Restart kernels and recompute affected mixed-gluon expressions after updating.

## Independent action comparison

The reference directly differentiates the determinant, inverse metrics and
lower-index Christoffel symbols through second order in labelled gravitons.
It does not call the source C tensors or source vertex routines. In particular,
δg⁻¹ = −h, δ²g⁻¹ = h₁h₂+h₂h₁, δsqrt(−g) = tr(h)/2, and
δ²sqrt(−g) = tr(h₁)tr(h₂)/4−tr(h₁h₂)/2. The gauge-fixing reference includes
the connection terms in ∇·A. Ghost orientation and the positive Fourier phase
are fixed before differentiating the displayed ghost action.

All ten h/hh families agree exactly at generic off-shell momenta and symbolic
D: AA, AAA, AAAA, antighost–ghost and A–antighost–ghost at each graviton order.
The labelled bosonic derivatives include identical-leg symmetrisation. A deliberately
changed coefficient fails the exact comparison. Colour expressions are compared
in a common unreduced trace representation, followed by ordinary polynomial
expansion; no numerical sampling, on-shell condition or D=4 limit proves these
comparisons. The retained references and exact residuals are in
`action-audit/run-action-r3`.

The combined FP matrix is triangular because the GR gauge depends only on g.
The model represents its factorised diagonal determinants. This does not assert
that the off-diagonal YM/diffeomorphism entry vanishes, or certify all ghost
Green functions in another BRST-field representation.

## Native verification

A disposable compatibility fixture verifies two distinct generic ghost index
structures, Grassmann loop signs against a commuting control, no Dirac objects,
a symbolic adjoint sum and a vector-ghost Lorentz cycle. This tests FeynArts
statistics/representation, not physical loop amplitudes. The delivered model uses
`F` for vector gravitational ghosts and `U` for scalar adjoint YM ghosts.

Every one of the 16 native contacts is constructed, converted and compared
exactly with its source coupling, including five- and six-leg contacts. The
external Grassmann permutation sign is recorded separately from the ordered
source coupling. A missing-contact negative control is rejected. The quartic
adjoint f f encoding is independently compared with the installed trace-basis
source before basis extraction. Four-argument patched `FASUNF` denotes a product
of two structure constants with a contracted dummy index.

The selected massless 2→2 trees have exact species-labelled inventories:

| Process | Channels | Overall coupling orders |
| --- | --- | --- |
| AA → AA | Quartic contact; s/t/u gauge exchange; s/t/u graviton exchange | g_s² and κ² |
| AA → Ah | hAAA contact; s/t/u gauge exchange | κ g_s |
| AA → hh | hhAA contact; s-channel graviton; t/u-channel gauge exchange | κ² |

All four external-leg Ward residuals vanish for each process. Internal routing
comes from native vertex conservation, and native graph factors are retained.
Only external-state colour markers are stripped; each internal sum is checked
as a repeated-index contraction term by term before colour simplification.
D and N remain symbolic, and s+t+u=0 is imposed for the massless tree kinematics.
For non-tested physical gravitons the fixture uses a factorised transverse
traceless polarisation. For the tested graviton the remaining gauge vector is
arbitrary. No four-dimensional helicity choice is used.

Removing the contact violates at least one Ward identity in each process.
For AA → Ah the graviton contraction alone is not a suitable missing-contact
negative control; the gauge-field contractions detect it. The physical complete
amplitudes are also checked to be nonzero. This evidence establishes the listed
physical tree checks, not equality of every possible external tensor component
or arbitrary process. The standalone native checks never load FeynGrav.

  were mapped incorrectly. Native colour labels follow external leg numbers,
  including uncoloured legs. Corrected r3 passed all contacts without model edits.

  the harness also used an incorrect patched-head context and disabled native
  momentum conservation. Corrected VVVV-r2 passed. VVVT-r2 passed all Ward tests
  but its chosen graviton-only negative control was inconclusive. Checking all
  legs gave the valid gauge-field negative controls in r3.

- Final integration harness r1 attempted to assign protected `$ScriptCommandLine`
  and stopped before package loading. The corrected harness uses the documented
  `FG_MODEL_TARGET` environment route; r2 passes all 25 checks.

No failed run is used as physical evidence. There was no accepted source
