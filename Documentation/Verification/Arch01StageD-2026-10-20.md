## Changes

### M09 — central validated mapping capability interpretation

- `CalcFormConverter/MappingEncoding.wl` now defines
  `mappingCapabilities[mapping_Association]`. It validates the identity version
  range, delegates version 6/7/8 algebra interpretation to the existing
  `tdAlgebraMapping`, validates the grouped result-layout gate and returns
  validated facts (`Version`, `AlgebraMapping`, `AlgebraVersion`, `Grouped`,
  `ResultLayout`).
- `CalcFormConverter/ImportReconstruction.wl` now uses this helper after the
  existing identity gate and `smValidateMapping`; the later version-specific
  epsilon, Dirac, colour and entry-order checks are unchanged. Specialised
  module-local version checks remain in place; this is a narrow central import
  boundary, not a replacement of every historical branch.
- SHA256: MappingEncoding `e78a2695...`; ImportReconstruction `d37e2536...`.

### M11 — shared placeholder audit

- `CalcFormConverter/ExportAssembly.wl` now defines small private helpers
  `templateMissingPlaceholders` and `templateUnknownPlaceholders` and uses them
  in `renderExport`. The existing required/unknown failure messages and payloads
  are preserved.
- `CalcFormConverter/PropagatorGroups.wl` uses the same missing-placeholder
  helper for `PropagatorFactors.frm.in`; stage-specific substitution remains
  local. No generic template framework was introduced.
- Cleanup revision: helpers accept a precomputed token-name list; `renderExport`
  tokenises once and reuses the names for missing/unknown checks;
  `PropagatorGroups` tokenises once after the unreadable-template short-circuit.
  Required-token ordering, duplicate handling, unknown-name sorting, existing
  regex behavior, failure messages/payloads and short-circuit handling are
  retained. The leftover `templateNames` assignment is now used.
- SHA256: ExportAssembly `0c9d789b...`; PropagatorGroups `5600e14e...`.

### M08 — retained, no forced split
